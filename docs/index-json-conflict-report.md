# data/index.json 冲突分析报告

## 事故概述

在 2026-08-30 至 2026-08-31 期间，每日出刊流水线与功能发布分支在 `data/index.json` 文件上发生多次覆盖冲突，导致最新一期作品索引被旧版本覆盖。

## 具体案例分析

### 冲突 commit 对比

**921b78a**（2026-08-31 出刊）：
```diff
-  "latest": "2026-08-29",
+  "latest": "2026-08-31",
   "issues": [
+    "2026-08-31",
     "2026-08-29",
```

**ebb4713**（2026-08-30 出刊）：
```diff
-  "latest": "2026-08-29",
+  "latest": "2026-08-30",
   "issues": [
+    "2026-08-30",
     "2026-08-29",
```

### 覆盖路径

1. 出刊流水线在独立分支（如 `artbook/t_3e03c7da-artsy`、`artbook/t_94a8e8ab`）上运行，生成当期的 `data/issues/YYYY-MM-DD.json` 并更新 `data/index.json` 的 `latest` 字段和 `issues` 列表。

2. 与此同时，功能发布分支（如布局修复、PWA icon 等）在开发时基于的是旧版本的 `main`，其 `data/index.json` 中的 `latest` 字段停留在更早的日期（如 `2026-08-29`）。

3. 当功能分支完成审核并合并到 `main` 时，如果未显式丢弃本分支携带的 `data/index.json` 改动，就会用旧版本的索引覆盖出刊流水线刚刚更新的最新索引。

4. 结果：赤拔在 iPhone 上打开首页时，看到的「最新一期」是功能分支携带的旧日期，而不是当天的新作品。

## 根因

**发布分支携带旧 `data/index.json` 合并到 `main`，覆盖了出刊流水线的最新索引更新。**

具体机制：
- 出刊流水线每日运行，更新 `data/index.json.latest` 字段和 `issues` 列表
- 功能发布分支在开发周期内不更新 `data/index.json`，保持开发起始点的旧状态
- 合并时 git 自动合并成功（因为双方修改的是不同行），但语义上是用旧索引覆盖了新索引
- 没有发布前检查机制来发现这种覆盖

## 解决方案

见 `HERMES.md`「踩过的坑」第 6 条及约定。
